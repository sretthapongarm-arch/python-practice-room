# 🐍 Python Practice Room

ห้องฝึกโจทย์ Python สำหรับผู้เริ่มต้น นักเรียนเลือกโจทย์ เขียนโค้ด และส่งตรวจได้ทันทีในเบราว์เซอร์ ครูล็อกอินเพื่อดูผลการส่งงานของนักเรียนทั้งห้อง

🌐 **Live Demo:** https://python-practice-room.vercel.app

📋 **เอกสารความต้องการ:** [MVP Requirements(1)](docs/MVP_REQUIREMENTS(1).md)

---

## ✨ ฟีเจอร์หลัก (MVP)

- เลือกโจทย์และเขียนโค้ด Python ได้ทันที ไม่ต้องสมัครสมาชิก
- กด "ลองรัน" เพื่อทดสอบกับตัวอย่าง และ "ส่งตรวจ" เพื่อตรวจกับชุดทดสอบทั้งหมด
- ตรวจโค้ดในเบราว์เซอร์ด้วย Pyodide (timeout 5 วินาที) ไม่ต้องมีเซิร์ฟเวอร์รันโค้ด
- ชุดทดสอบซ่อน นักเรียนเห็นแค่ ผ่าน หรือ ไม่ผ่าน
- บันทึกการส่งงานและผลรายข้อลงฐานข้อมูล
- ครูล็อกอินดูรายการส่งงาน โค้ด ผลรายข้อ และสรุปต่อโจทย์

## 🛠️ ภาษาและเทคโนโลยีที่ใช้

### ภาษา (Languages)

| ภาษา | ใช้ทำอะไร |
|------|-----------|
| TypeScript / JavaScript | เขียนหน้าเว็บและตรรกะฝั่งผู้ใช้ |
| Python | ภาษาที่นักเรียนเขียนในโจทย์ (ตรวจด้วย Pyodide) |
| SQL | โครงสร้างและการ query ฐานข้อมูล PostgreSQL |
| HTML / CSS | โครงสร้างและหน้าตาเว็บ |

### เทคโนโลยี (Tech Stack)

| ส่วน | เทคโนโลยี | หน้าที่ |
|------|-----------|---------|
| เฟรมเวิร์ก | Next.js 14 | routing, หน้าเว็บ, หน้า `/teacher` |
| UI | React 18 | สร้างส่วนต่อประสานผู้ใช้ |
| ภาษาเขียนโค้ด | TypeScript 5 | ตรวจชนิดข้อมูลตอนพัฒนา |
| ตัวตรวจโค้ด | Pyodide | รัน Python ในเบราว์เซอร์ |
| ฐานข้อมูล | Supabase (PostgreSQL) | เก็บโจทย์ ชุดทดสอบ และผลการส่งงาน |
| ล็อกอินครู | Supabase Auth | ปิดการสมัครสาธารณะ ใช้บัญชีที่ครูสร้างไว้ |
| โฮสต์ | Vercel | Deploy อัตโนมัติจาก GitHub |
| เก็บโค้ด | GitHub | Version control |

## 🧩 สถาปัตยกรรมโดยย่อ

```
นักเรียน ──► Next.js (Vercel) ──► Pyodide (รันในเบราว์เซอร์) ──► ผลตรวจ
                  │
                  └──► Supabase: problems, test_cases, submissions, execution_results
ครู ──► /teacher ──► Supabase Auth ──► ดูผลการส่งงาน
```

ฐานข้อมูลหลัก 4 ตาราง: `problems`, `test_cases`, `submissions`, `execution_results`

## 🚀 วิธีรันในเครื่อง

```bash
git clone https://github.com/<your-username>/<your-repo>.git
cd <your-repo>
npm install
cp .env.example .env.local
npm run dev
```

เปิด http://localhost:3000

## 🔐 Environment Variables

สร้างไฟล์ `.env.local` แล้วใส่ค่าจากหน้า Settings → API ใน Supabase

| ตัวแปร | ความหมาย |
|--------|----------|
| `NEXT_PUBLIC_SUPABASE_URL` | URL ของโปรเจกต์ Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public key |

> ห้าม commit ไฟล์ `.env.local` ขึ้น GitHub

## ☁️ การ Deploy

1. Push โค้ดขึ้น GitHub
2. Import repo ใน [Vercel](https://vercel.com)

4. กด Deploy และทุกครั้งที่ push ระบบจะ deploy ใหม่ให้อัตโนมัติ

**ข้อควรรู้ของแผนฟรี:** Vercel Hobby ห้ามใช้เชิงพาณิชย์ และ Supabase Free จะพักโปรเจกต์ถ้าไม่มีคนใช้ราว 1 สัปดาห์ รายละเอียดดูใน [MVP Requirements](docs/MVP_REQUIREMENTS.md)

# 📋 MVP Requirements: Python Practice Room

เอกสารความต้องการของรุ่น MVP ที่รันบนแผนฟรี (Vercel Hobby + Supabase Free + Pyodide)

## 1. เป้าหมายและกลุ่มผู้ใช้

- **ผู้ใช้เป้าหมาย:** ครูหรือโรงเรียนที่สอน Python ระดับต้น (ม.ปลาย, ปี 1, โรงเรียนกวดวิชา)
- **ปัญหาที่แก้:** ครูตรวจโค้ดนักเรียนทีละคนด้วยมือ และไม่เห็นภาพรวมว่าใครติดข้อไหน
- **สิ่งที่ MVP ต้องพิสูจน์:** ครูยอมใช้กับห้องจริง 1 ห้อง และนักเรียนส่งงานผ่านระบบจนจบชุดโจทย์

## 2. ต้องมี (Must)

| กลุ่ม | ความต้องการ | สถานะ |
|-------|-------------|-------|
| นักเรียน | เปิดเว็บแล้วเลือกโจทย์ได้โดยไม่ต้องสมัคร | ✅ มีแล้ว |
| นักเรียน | เขียนโค้ด กด "ลองรัน" และ "ส่งตรวจ" | ✅ มีแล้ว |
| ตรวจโค้ด | รันด้วย Pyodide เทียบกับชุดทดสอบ มี timeout 5 วินาที | ✅ มีแล้ว |
| ตรวจโค้ด | ชุดทดสอบซ่อน เห็นแค่ผ่านหรือไม่ผ่าน | ✅ มีแล้ว |
| ข้อมูล | บันทึก `submissions` และ `execution_results` | ✅ มีแล้ว |
| ครู | ล็อกอิน ดูรายการส่งงาน โค้ด และผลรายข้อ | ✅ มีแล้ว |
| ครู | สรุปต่อโจทย์ (กี่คนส่ง กี่คนผ่าน) | ✅ มีแล้ว |
| ครู | สร้างและแก้โจทย์เองในเว็บ | ⬜ ยังไม่มี (ตอนนี้ต้องแก้ใน Supabase) |
| นักเรียน | ใส่รหัสห้อง เพื่อให้ครูแยกผลรายห้อง | ⬜ ยังไม่มี |

สองข้อสุดท้ายสำคัญที่สุดก่อนให้ครูทดลองใช้ เพราะถ้าครูต้องเปิดฐานข้อมูลเอง จะไม่มีใครใช้ต่อ

## 3. ควรมี (Should)

- [ ] ครู export ผลเป็น CSV เพื่อกรอกคะแนน
- [ ] ครูดูรายชื่อนักเรียนที่ยังไม่ส่งงาน
- [ ] นักเรียนดูประวัติการส่งของตัวเอง
- [ ] โจทย์มีหมวดหรือลำดับ (ตัวแปร, เงื่อนไข, ลูป)
- [ ] ข้อความทั้งหมดเป็นภาษาไทย รวมถึงคำอธิบาย error ที่เข้าใจง่าย
- [ ] ชุดโจทย์ตั้งต้น 15-20 ข้อ เรียงจากง่ายไปยาก

## 4. ยังไม่ทำใน MVP (Won't)

- การให้เกรดหรือสอบจริง เพราะตรวจฝั่งเบราว์เซอร์ นักเรียนแก้ผลได้
- การตรวจความคล้ายของโค้ด (plagiarism)
- แชต ฟอรัม หรือระบบคะแนนสะสม
- ภาษาอื่นนอกจาก Python
- แอปมือถือ (เว็บใช้บนมือถือได้ แต่ไม่ได้ออกแบบให้เขียนโค้ดบนจอเล็ก)

## 5. ข้อจำกัดของแผนฟรี

- **Vercel Hobby** ห้ามใช้เชิงพาณิชย์ หากจะเก็บเงินต้องย้ายแผนหรือโฮสต์ที่อื่น
- **Supabase Free** จะพักโปรเจกต์หากไม่มีการใช้งานราว 1 สัปดาห์ ก่อนเปิดคลาสควรเข้าเว็บสักครั้งหรือกด Restore
- **Supabase Free** มีที่เก็บข้อมูลจำกัด (ประมาณ 500 MB) พอสำหรับหลักพันการส่งงาน
- **Pyodide** โหลดประมาณ 10 MB ในครั้งแรก ห้องที่อินเทอร์เน็ตช้าอาจรอนาน

> เงื่อนไขของแต่ละบริการอาจเปลี่ยน ควรตรวจหน้าราคาล่าสุดก่อนใช้งานจริง

## 6. ความปลอดภัยขั้นต่ำ

- ครูล็อกอินด้วย Supabase Auth และปิดการสมัครสมาชิกสาธารณะ
- เก็บเฉพาะชื่อที่นักเรียนกรอกเอง หากใช้กับโรงเรียนจริงควรมีข้อความแจ้งการเก็บข้อมูลตาม PDPA
- ควรเพิ่มการจำกัดจำนวนการส่งต่อนาที เพราะตอนนี้ใครก็ส่งงานเข้าฐานข้อมูลได้

## 7. ตัวชี้วัดความสำเร็จของการทดลอง

- ครูอย่างน้อย 2-3 คนใช้กับห้องจริง
- นักเรียนอย่างน้อย 70% ส่งงานครบอย่างน้อย 3 ข้อ
- ครูบอกว่าประหยัดเวลาตรวจงานได้ และยินดีใช้ต่อหรือจ่ายเงิน
- ครูกลับมาใช้ซ้ำเองในสัปดาห์ที่สอง

## 8. ลำดับงานที่แนะนำ

1. หน้าสร้างและแก้โจทย์สำหรับครู
2. รหัสห้อง และกรองผลตามห้อง
3. Export CSV
4. ชุดโจทย์ตั้งต้นภาษาไทย
5. ถ้าต้องใช้ให้คะแนนจริง ย้ายการตรวจไปฝั่งเซิร์ฟเวอร์

ข้อมูลนี้ยืนยันแค่ว่าระบบทำอะไรได้ ยังไม่ยืนยันว่ามีลูกค้าอยากซื้อ ต้องทดลองกับครูจริงเพิ่ม
